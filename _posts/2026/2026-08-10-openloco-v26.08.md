OpenLoco v26.08 is out! The past two weeks has seen a good chunk of work so we thought we'd do an early release this month.
It also comes with a feature that people have been asking for, for quite some time, Signal auto placement!

Please find the [download](https://openloco.io/download/) on our website, or read the
[changelog](https://github.com/OpenLoco/OpenLoco/blob/v26.08/CHANGELOG.md) on GitHub.


## Signal auto placement

I'm never quite sure what to call this feature but now in the signal placement tool you can change the mode to repeated
placement. When in repeated placement mode the track will be walked along placing signals every step track pieces. This
will greatly speed up how long it takes to place all your signals at nice even spaces. The auto placement will stop as
soon as it hits a junction, another signal, or a station. If for some reason though you decide you wanted to adjust the
spacing of already placed signals we also have you covered. Whilst in repeated placement mode a right click removal of a
signal will remove all signals in the block (the track between a junction or station). I hope you enjoy this quality of
life feature. I'll now go through a little history of the feature.

The feature was first requested back in 2018 but at the time we didn't have enough of the code implemented to realistically
implement it. In 2021 @LeftOfZen noticed the issue and started trying to implement it. In 2021 we had almost enough of the
code implemented to do the feature but knowledge of track iteration was lacking. All this meant @LeftOfZen had quite a few
issues making the feature work so it was never completed. During 2024 I implemented a lot of the Company AI code. One function
in there was `placeAiAllocatedSignalsEvenlySpaced` which was a function that would place signals evenly spaced along a track.
If I had been thinking about this feature at the time we could have very easily copied this code. Instead I forgot about it
until @MasterHellish made a YouTube video in 2026 lamenting about the lack of this feature. You would think that would have
reminded me that I had basically already implemented it in the Company AI code but it didn't. Instead I implemented it all
from scratch again. The reason I didn't immediately put two and two together is that the Company AI track iteration has to
iterate over track that is `pre allocated` to the company. Its a subtle difference that meant it used a slightly different
function name so didn't turn up when I was searching. After finishing the feature I went back and found the Company AI code
and it is almost identical, doh.

Are there any other features that you would like to see in OpenLoco? Perhaps they have also fallen through the cracks? If its
a feature like this where it doesn't require saving anything new but is more an improvement to the interface then perhaps we
could implement it. Feel free to bring up ideas on discord (preferably referencing an issue from GitHub).

## Try fix Tutorials

The tutorials in Locomotion are not great. They all depend on replaying a mouse pointer moving and clicking on UI elements.
Whenever we change a UI element there is a high likelihood that the tutorial will break. The tutorials also must be run at
a certain window size. We do plan on completely reworking the tutorials in the future but for now we just want to make them
mostly work.

@AaronVanGeffen and @LeeSpork both worked on the tutorials this month getting them finally working again. Its been a bit of
a constant battle as we have had a few UI and under the hood changes that broke many tutorial assumptions. Also just when
they thought the job was complete I merged my signal auto placement which changed the UI such that a tutorial broke again :).
